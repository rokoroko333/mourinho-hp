# レビュー用スキルの評価

`.claude/skills/pr-review/SKILL.md` を変える PR では、変えたスキルで過去の PR をもう一度レビューして、
以前は見つけられた問題を見落とすようになっていないか（回帰していないか）を確かめます。
スキルの単体テストにあたるものです。

## 評価ケース

どれも、1周目のレビューで指摘が出て、あとのコミットで直した PR です。`差分` は1周目にレビューした時点のものです。

| ケース | 差分 | 見つけるべき問題 | 場所 |
|---|---|---|---|
| #12 | `695266e..78c20cc` | 語の境目で切る `clip` が、空白のない文字列で `lastIndexOf` が -1 になり、末尾が落ちる | `scripts/build.mjs` の `clip` |
| #14 | `4ddfef9..6ced7e8` | 共有画像を先に消してから作り直すので、途中で失敗するとコミット済みの画像が消えたままになる | `scripts/og.mjs` の `rmSync(OUT, …)` |
| #18 | `ace4972..6b666c7` | `hidden` のステップが、要素がなくても通る（セレクタの打ち間違いを見逃す） | `scripts/verify.mjs` の `step.hidden` |
| #19 | `ace4972..5d07f17` | 正規表現でコードを調べるテストの一部が、対象を何件見つけたかを確かめておらず、書き方が変わると空振りして緑のままになる | `test/rules.test.mjs` |
| #30 | `477ef57..dc95ab2` | CSS の置換で `.tag-list .pill` の規則が `.pill` に書き換わり、タグ一覧の見た目が壊れる | `src/assets/styles.css` |

## 進め方

1. 実装とは別のスレッド（またはサブエージェント）で、ケースごとに独立して実行する。
   渡すのは変更後のスキルと差分だけにし、このファイルの「見つけるべき問題」は見せない。
   差分は `git fetch --no-prune --shallow-since=2026-10-27 origin main` のあと `git diff <差分>` で取り出す
   （浅い clone ではケースのコミットが届かないため）。
2. 実装スレッドが、各ケースの出力を次の3項目で0〜2点に採点する（1ケース6点満点）。
   - **発見**: 見つけるべき問題を指摘したか（2: 指摘した、1: 近い所を指摘した、0: なし）
   - **根拠**: `ファイル:行` と、どんな入力・状態で何が起きるかを書いたか
   - **重大度**: 必須か推奨として出したか（任意や「問題なし」は0）
3. 変更前のスキルでも同じケースを実行して比べる。合計点が下がったケースがあれば、スキルを直すか、
   下がった理由と、それでも変える理由を PR に書く。
4. 点数の表を PR の「検証結果」に貼る。

## ケースの足し方

レビューで「必須」の指摘が出て直した PR は、ここに1行足せます（1周目の差分・見つけるべき問題・場所）。
全部で10件を目安にし、増えすぎたら同じ種類の問題のケースから消します。
