- 2026-10-29 #12 文字列を語の境目で切る処理は、空白がないと `lastIndexOf` が -1 になり末尾が落ちる。境目がないときの切り方も書く（検証: 2026-10-29）

- 2026-10-29 #18 Pages は 404.html がないと、存在しないパスにトップページを 200 で返す。ステータスだけで「ページがある」と判断しない（canonical のパスで確かめる）（検証: 2026-10-29）

- 2026-10-30 #43 文書と実物の対応を確かめるテストは、行（キー）があるかだけでなく中身（パスなど）も照合する。キーだけだと slug を変えても古いパスのまま通る（検証: 2026-10-30）

## うまくいった手順

- 2026-10-29 #2 実装の経緯を渡さない別のサブエージェントに pr-review を任せると、レビューが1回で終わり先入観も入らなかった（検証: 2026-10-29）
- 2026-10-29 #6 レビューのルーティンに GitHub のフック（PR の作成・更新）を付けると、プッシュ直後にレビューが自動で付いた（検証: 2026-10-29）
- 2026-10-29 #15 画面撮影では確かめられないクリック後の動作は、ヘッドレス Chrome を DevTools Protocol（Node 22 の WebSocket）で動かし、クリックして DOM とコンソール（CSP 違反）を見ると確かめられた（検証: 2026-10-29）
- 2026-10-29 #16 下書きの PR を「ready」にしてもフック（opened・synchronize）は起動しない。PR 本文を書き終えてから RemoteTrigger の run でレビューを起動すると、空の本文をレビューされずに済んだ（検証: 2026-10-29）
- 2026-10-29 #20 名言の出典調べは、5本ずつのサブエージェントに「ページを開いて本文に引用があることを確かめた出典だけ」を返させると、文脈の誤り（harry-potter は Chelsea でなく Real Madrid）や、出典のない名言（2本）を見つけられた（検証: 2026-10-29）
- 2026-10-30 #29 名言の日付は、出典が発言の暦日をはっきり書いているときだけ日まで載せ、「日曜」「昨夜」や記事の公開日からは割り出さない（年だけにする）。調査の指示に最初から書くと、迷いと手戻りが減った（検証: 2026-10-30）
- 2026-10-30 #32 `npm run screenshot` は、パスを渡さないとトップ3言語しか撮らない。`--height` は次の引数を値として読むので、値を書き忘れるとそのパスが高さに取られて撮られない。新しいページの PR では `--height 4200 /trophies/ /pt/titulos/` のように、パスと高さを渡す（検証: 2026-10-30）
- 2026-10-30 #33 事実（タイトルなど）を別のページにも出すときは、カードを関数（`trophyCard`）にまとめて使い回し、どのページでも出典が一緒に出るようにする。時代との結びつけは `era` だけで行い、他の時代の項目が混ざらないことをテストで確かめる（検証: 2026-10-30）
- 2026-10-30 #34 KV に入れる JSON の形を変えたら、Pages と Worker の両方をデプロイする必要があることを PR に書き、古い形の JSON でも画面が落ちないようにする（検証: 2026-10-30）
- 2026-10-30 #35 数字は出典どうしで食い違う部分だけを見送る（試合数と勝利数が一致し、分けと負けが割れるなら、分けと負けを「—」にして注記する）。単一の出典にしかない通算成績は、クラブ別の合計と照らし合わせて、合わなければ載せない。勝率は出典の数字からビルド時に計算し、言語ごとの書式（`Intl.NumberFormat`）で出す（検証: 2026-10-30）
- 2026-10-30 #36 発言の場面（試合の前か後か、スコア）は、出典の本文に書かれていることだけを書く。「If we win today」のように時制から読み取れても、出典が前後を書いていなければ「〜について」とする。調査メモの要約を信じず、場面は記事を開いて確かめる（検証: 2026-10-30）
- 2026-10-30 #37 「時点の数字」を出すページで、その時点より後の試合を「主な試合」に並べるときは、カードに「この成績の時点より後の試合」と出す。出典が大会別の内訳を書いていなければ、そのこともページに書く。出典の日付と `asOf` は、数字を数えた記事にそろえる（検証: 2026-10-30）
- 2026-10-30 #38 日付が実在する日かのテストは `Date.parse` では足りない（2001-02-31 も通る）。`toISOString().slice(0, 10)` で往復して比べる。ビルドと `app.js` に同じ規則があるときは、両方のコメントで相互に参照する（検証: 2026-10-30）
- 2026-10-30 #39 ESPN の試合ページの日付は、地域版によって時差で翌日になる（espn.com.au）。日付の出典には espn.com か africa.espn.com を使い、他の地域版は英国の昼の試合のときだけ使う（検証: 2026-10-30）
- 2026-10-30 #40 データを末尾に足すファイル（`onthisday.json`・`remarks.json`）は、ビルドで並べ替えているので順番を気にしなくてよい。並べ替えをやめるときは、データの順番もそろえる（検証: 2026-10-30）
- 2026-10-30 #41 PR やメモに書く日付は日本時間で、GitHub の表示（UTC）とは1日ずれることがある。レビューで日付のずれを指摘されたら、どちらの時刻で書いたかを返す（検証: 2026-10-30）
- 2026-10-30 #42 時刻に依存する関数（今日の日付で選ぶものなど）は、日付を引数で受けて `scripts/content.mjs` に置き、日付を固定した単体テストで分岐（当日・次・年末の折り返し・UTC の境目）を確かめる（検証: 2026-10-30）
- 2026-10-30 #44 表示を確かめるテストは、消えたら困る文字列そのもの（`longDate` で書いた時点の日付など）で判定する。年や共通の class は出典の日付や別の要素にも含まれ、注記が消えても通ってしまう。直したら、その要素を消してテストが落ちることも確かめる（検証: 2026-10-30）
- 2026-10-30 #47 スキルの重大度を例外の列挙から判断基準1つに書き直すとき、消した例外（「条件しだいで壊れるなら任意にしない」）の意味を定義に残さないと、評価で潜在バグが任意に落ちた（#14）。書き直しは評価で1行ずつ戻すかを決める（検証: 2026-10-30）

## 環境の事実

- 2026-10-29 #2 ESPN はボットの User-Agent に 403 を返す。`season=Y` は Y 年開始のシーズンで終わった試合だけ、今後の試合は `fixture=true`（検証: 2026-10-29）
- 2026-10-29 #3 Google News の出典名は大文字小文字が媒体ごとに違う（MARCA・Diario AS・SPORT・EL PAÍS）。`site:` の実データで確かめてから書く（検証: 2026-10-29）
- 2026-10-29 #5 Google News は Cloudflare Workers からの取得に「automated queries」の 503 を返すことが多い。手元で取れても本番では取れないので、`wrangler dev --remote` で確かめる（検証: 2026-10-29）
- 2026-10-29 #6 ヘッドレス Chrome は幅500px未満の窓を作れない。390 を指定しても幅500で描画され、画像の右側が切れる（検証: 2026-10-29）
- 2026-10-29 #7 Cloudflare から取れる媒体の RSS: Guardian（Accept に XML が必要）・BBC・Marca・AS・MD・El País・Record・A Bola。Sport はボットに 406、O Jogo は RSS なし（検証: 2026-10-29）
- 2026-10-29 #8 CI（GitHub Actions）は `npm test` 内でビルドもする（test/build.test.mjs が CSP 違反になるインライン要素を検査）。`wrangler pages dev` は `_headers` を返すので CSP をローカルで確かめられる（検証: 2026-10-30）
- 2026-10-29 #12 `~/.gitconfig` に `fetch.prune = true` があると、明示した refspec の fetch が書いた ref を消す。スクリプトで fetch するときは `--no-prune` を付ける。worktree からは `FETCH_HEAD` が見えない（検証: 2026-10-29）
- 2026-10-29 #12 ヘッドレス Chrome は普段使いの Chrome と同じプロファイルだと固まることがある。`--user-data-dir` で使い捨てのプロファイルを渡す（検証: 2026-10-29）
- 2026-10-29 #15 YouTube の oEmbed（`/oembed?url=…`）は、実在する動画ならチャンネル名とタイトルを返し、埋め込み禁止なら 401 を返す。UEFA の動画は埋め込み禁止だった（検証: 2026-10-29）
- 2026-10-29 #18 クラウドのセッションは root で動くので、Chrome は `--no-sandbox` がないと起動しない。ヘルパープロセスが残ってプロファイルを消せないので、プロセスグループごと止める。サイトは `scroll-behavior: smooth` なので、クリック前のスクロールは `behavior: 'instant'` にする（検証: 2026-10-29）
- 2026-10-29 #19 `node --test` はテストファイルを並列で実行する。複数のファイルが dist/ をビルドすると ENOTEMPTY で落ちるので、ビルドは build.test.mjs だけで行う（検証: 2026-10-30）
- 2026-10-29 #20 `npm run dev` はポート 8788 が使用中だと起動に失敗するが、`npm run verify` や撮影はその別のサーバーを相手に走ってしまう。起動後にログの `Address already in use` と `lsof -iTCP:8788` を確かめる（検証: 2026-10-29）
- 2026-10-29 #21 ポート 8788 は、同じ PC の別プロジェクト（pj_kiroko_electoric）の開発サーバーも使う。`npm run dev` の起動直後はログにエラーが出ないことがあるので、`curl localhost:8788 | grep 'Infinito Mourinho'` で自分のサイトか確かめるか、`npx wrangler pages dev dist --port 8790` と `--base http://localhost:8790` を使う（検証: 2026-10-29）
- 2026-10-30 #25 ESPN の記事番号（`/id/37…`）は古い記事の付け直しで、公開順ではない。2019〜2021年の記事も 375xx〜376xx 番台。年代はページの `datePublished` で確かめる（検証: 2026-10-30）
- 2026-10-30 #29 realmadrid.com の英語の記事は、AI 翻訳の注記が付くことがあり、JavaScript で描かれるため curl では本文を確かめられない。2026年の Real Madrid の発言は、独立した報道機関の記事で確かめる（検証: 2026-10-30）
